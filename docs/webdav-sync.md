# WebDAV 同步

设置入口：**设置 → 账号与同步 → WebDAV**。点击「添加 WebDAV」，填写 HTTPS WebDAV 根地址（填入坚果云地址时会显示获取应用密码的说明链接）、同步目录、用户名和应用密码，点击「保存并开启同步」。服务器验证通过后连接卡片才出现；无法连接时表单保持打开并显示原因，不会留下无效连接。每台设备分别设置连接；凭据不通过 Chrome 或 WebDAV 同步。

## 坚果云免费版接入

1. 注册个人免费账号。2026-10-01 的账号页面确认免费额度为每月上传 1 GB、下载 3 GB，适合先验证配置、自定义图标和少量壁纸同步；这是流量额度，不是 1 GB 的总存储上限。[官方额度](https://www.jianguoyun.com/s/pricing)
2. 为 Lumno 单独生成应用密码。本次新账号的网页版「账户信息 → 安全选项 → 第三方应用管理」提示需要使用客户端；在官方客户端登录后，进入「设置 → 第三方应用管理」，创建名为 `Lumno` 的授权。使用应用密码，不使用账号登录密码。[官方客户端](https://www.jianguoyun.com/s/downloads)、[WebDAV 授权说明](https://help.jianguoyun.com/?p=2064)
3. 在 Lumno 的 WebDAV 表单填入以下内容：

   | 字段 | 内容 |
   | --- | --- |
   | 服务器地址 | `https://dav.jianguoyun.com/dav/` |
   | 同步目录 | `lumno` |
   | 用户名 | 注册坚果云的邮箱 |
   | 应用密码 | 客户端中为 Lumno 生成的应用密码 |

4. 可先点击「测试连接」。它只写入随机测试文本、创建随机测试目录并清理探针，不上传个人配置或图片；随后点击「保存并开启同步」，十分钟内会复用这次测试结果，不重复探测。测试优先验证禁止覆盖的 MOVE 独占锁，并检查强 ETag 条件写入；不能仅凭账号已注册或能够上传文件就认为支持多设备安全同步。
5. 第二台设备使用同一账号和目录配置连接，远端已有数据时选择「使用远端配置」。首次启用前会自动保留本机完整备份；Chrome 继续按原有路径同步配置，WebDAV 同时同步图片。

免费版 WebDAV 官方限制为每 30 分钟 600 次请求；大量图片首次同步和多台设备会共同消耗账号流量和请求额度。2026-10-02 使用已注册的免费账号运行当时的 `dav-lock-3` 客户端，连接测试通过并选择 `collection-lock`：读取响应没有可用的强 ETag，目录竞争返回 201 / 405，删除返回 204，删除后重新创建返回 201。这是旧检测的一次成功结果；用户随后报告反复开关时偶发 201 / 201，说明不能依赖该服务的并发 MKCOL。原独立 MOVE 探测返回 201 / 409，两方内容均保留；新版在此基础上增加占用目标不可覆盖、删除及重新获取、锁归属验证，尚未完成新版的实机验证。

正常界面不显示内部版本号。设置页同时校验后台的连接检测版本 `dav-lock-5` 和同步流程版本 `dav-multi-1`。新页面检测到旧后台时，会立即提示重新加载扩展并刷新设置页，阻止连接测试、启用和写入，仍允许暂停已启用的同步。开发版应在 Chrome 扩展管理页重新加载现有 Lumno，再刷新设置页；若加载的是解压的副本，先将最新版文件更新到它原有的加载目录，保留原安装和数据。

连接失败时，设置页会附上安全诊断标识，例如 `dav-lock-5 / move-race / 201,201`，分别表示检测版本、失败步骤和 HTTP 响应码；不包含用户名、密码或服务器正文。重复出现同一提示时，应先拿到真实响应，勿直接移除并发保护。

开发者可使用 `node scripts/probe-webdav.js` 做独立服务探测：在本机 `.tmp/webdav/provider-probe.private.json` 填写 endpoint、directory、username、password；脚本校验后立即删除该临时凭据文件，只创建随机探针，不读取 Chrome 数据，不上传个人配置或媒体。它验证当前连接检测并另做独立 `MOVE / Overwrite: F` 竞争探测；一方 201、另一方拒绝（405 / 409 / 412 / 423 / 500）只有在两方内容均保留时才算通过；两方都被拒绝时，目标必须仍不存在且两方内容均保留。结果保存在 `.tmp/webdav/provider-probe-result.json`，只有响应码、ETag 类型与内容是否保持不变等信息，不包含认证头或响应正文。

## 保存、开关与并行同步

WebDAV 标记为 Beta，标识右侧使用设置页共用的 info 图标说明稳定性与反馈入口。点击「添加 WebDAV」展开与站内搜索共用样式的表单。卡片标题显示服务商名称或服务器地址，旁边是与 Chrome 内置同步相同的状态胶囊（未开启、已暂停、正在同步、已同步及相对时间、需要选择、存在冲突、同步失败、需要恢复）；下一行显示用户名与目录。需要用户处理的内容（初始版本选择、冲突、失败原因与重试、恢复备份）显示在卡片下方的虚线区域，诊断标识通过「复制诊断信息」获取，不混在提示文字里。「立即同步」图标只在同步开启时显示。使用卡片上的编辑按钮展开表单，一次编辑一条连接。每条连接分别开启或暂停同步。同一服务器、目录和用户名只能添加一次。配置与应用密码保存在扩展专属 IndexedDB，刷新页面或重启后台后可继续使用；密码不会返回到设置页，留空可保留同一服务器、同一用户的已保存密码。未修改任何内容时保存不会打断同步；修改了正在运行的连接，保存后会自动重新开启并按需重新验证；更换服务器或目录会清除旧服务器的合并基线和同步时间。同一地址、目录、用户、密码及检测版本复用已验证的并发能力，反复开关和后台重启不重复创建探针；更改连接信息或升级检测版本会重新验证，主动点击「测试连接」始终执行新探测。


可添加多个 WebDAV 连接。每条连接分别保存凭据、合并基线、同步时间、冲突与替换备份，分别使用定时任务；远端读写并行执行，一个连接离线或等待处理不阻塞其他连接。写入同一份本机配置与媒体时串行提交，并校验本机变更版本；捕获到旧版本的任务等待下一次同步，不覆盖其他连接刚刚应用的内容。中断的本机写入恢复前，其他连接不会上传部分状态。所有连接共享同一份本机配置，不同服务器同时修改同一项仍需选择冲突版本。

卡片上的删除按钮使用站内搜索相同的内联确认组件。确认后暂停并移除这条本机连接及其凭据、同步记录与连接备份，清除对应定时任务；服务器文件、当前本机配置、图片和其他连接保留。最后一条删除后回到仅有「添加 WebDAV」入口的未配置状态。旧单连接配置在升级后原位保留，已有凭据与合并记录不重新初始化。

| 状态 | 配置来源 | WebDAV | Chrome Sync |
| --- | --- | --- | --- |
| 未配置 / 已保存但关闭 | Chrome Sync + 本机媒体及快捷方式溢出区 | 不同步 | 保持原有读写、自动同步和手动同步 |
| 开启 | 同上 | 同步配置与自定义媒体 | 同时运行，仍接收其他设备的更新 |
| 暂停 / 离线 / 冲突待处理 | 同上 | 停止同步或等待处理 | 继续运行 |

启用与暂停不会把配置来源切换到本机，也不会重命名或禁用 Chrome 同步。Chrome 配置变更与本机图片变更都会触发 WebDAV，后台每五分钟检查一次远端。WebDAV 的最后成功同步时间单独显示，连接测试、操作反馈和失败不会覆盖该时间。

首次连接已有远端数据时必须选择初始版本。后续同步按上次成功基线进行三方合并；修改同一配置项、快捷方式与图标、壁纸与选图时显示冲突内容。冲突卡片上的「查看差异」按本机和服务器两列列出相对上次同步的改动：设置项显示两边的值，快捷方式与壁纸显示新增、删除、修改和顺序变化（每类最多列出 6 个名称并给出总数）。选择本机或远端仅决定冲突内容，其他独立改动仍合并。「稍后处理并暂停」保留两边数据，Chrome 同步继续运行。替换前保存本机副本，覆盖远端前保存远端 JSON 快照；恢复本机备份会暂停该 WebDAV 连接。恢复按钮仅在配置替换中断、需要恢复完整本机状态时显示，普通连接卡片不常驻显示。

应用远端配置前先验证 Chrome 单项与总容量，超限时拒绝应用，保留原有 Chrome 数据。快捷方式沿用现有分块与本机溢出机制；图片仍保存在本机 IndexedDB，不写入 Chrome Sync。旧版本的本机主来源模式仅在完整配置能放入 Chrome 时迁移，不做截断或部分替换。

凭据和合并基线在同一 IndexedDB 记录内提交。修改本机前记录完整应用日志：后台重启后，完成的应用会补齐同步记录；未完成的应用暂停上传，保留原始完整副本供恢复，避免把部分状态同步到其他设备。

## 同步范围

- 原有 Chrome 配置白名单：主题、搜索源、黑名单、新标签页设置等；远端 JSON 文件上限 2 MiB；配置仍遵守 Chrome 同步容量限制，避免影响原有同步。
- 普通快捷方式、书签文件夹快捷入口和上传的自定义 PNG 图标；当前快捷方式总数限制不变。文件夹入口同步根目录类型、相对路径及内容摘要；每台设备的书签 ID 映射只保存在本机，不上传。
- 全部上传的自定义壁纸及缩略图、浅色/深色选图；上传后的 WebP 文件上限分别为 2 MiB / 160 KiB。沿用现有压缩结果，不上传原图。内置壁纸只同步选择。
- Chrome 同步不包含图片；配置写回前验证容量，不会为启用 WebDAV 删除或缩减现有 Chrome 配置。

书签数据库、浏览历史、当前标签页、自动取得的 favicon 缓存及 WebDAV 凭据不加入远端快照。现有 JSON 导出仍是配置导出，不包含图片；完整图片备份由 WebDAV 和本机备份承担。

文件夹内容继续使用 Chrome 书签同步。拖入快捷区时直接绑定选中的原文件夹，不再次选择。其他设备自动匹配本机目录；书签尚未到位或有多个无法区分的候选时，入口不显示、不占位置，底层同步记录与顺序保留，匹配成功后自动显示。已绑定文件夹改名或移动时由后台更新定位信息。原目录删除后，本机不会自动把同名新目录当作原目录。

旧文件夹记录在来源设备能唯一确认原目录时自动迁移；无法确认的旧本机 ID 不会直接当成另一设备的目标。迁移前尚未具有可迁移定位信息的旧入口继续留在本机。

首次同步可迁移文件夹入口后，远端 JSON 使用协议版本 2，并保持该版本。版本 2 与原有 `v1/` 存储目录共用位置；新客户端可读旧版本 1，旧客户端会拒绝版本 2，防止遗漏文件夹入口后覆盖远端。请在两台设备都更新扩展后使用文件夹入口同步。

## 协议与文件

```text
<服务器根目录>/<同步目录>/v1/
  state.json                 # 配置与媒体引用
  assets/<sha256>.png|webp    # 按内容去重的二进制图片
  snapshots/<uuid>.json      # 覆盖前的远端配置快照
```

使用 GET、HEAD、PUT、MKCOL、MOVE、DELETE，无需 PROPFIND。连接测试会创建并删除独立探针文件，验证读写、强 ETag、正确/错误 If-Match 以及 If-None-Match。独占锁优先使用 MOVE / Overwrite: F：两个带不同 owner.txt 的私有目录竞争同一目标，必须只有一个返回 201，失败方被拒绝；同时验证目标属于获胜者、失败方内容保留、获胜源已移走、再次竞争不会覆盖，以及删除后可以重新获取。各服务对占用目标的拒绝码不同：RFC 4918 为 412，坚果云为 409，Go x/net/webdav（rclone、AList 等）为 423，nginx 为 405，Apache、WsgiDAV 与 Nextcloud 在请求真正重叠时为 500。这些拒绝码只有经内容验证后才被接受，任何状态码都不单独代表成功或失败。Nextcloud 的文件锁可能同时拒绝两方；目标仍不存在且两方内容保留时视为互斥成立，再按顺序获取目标继续验证。两方都返回 201 的服务直接拒绝。只有服务器明确不支持 MOVE（405 / 501）时才退回通过 201 / 405 并发检测的 MKCOL；探测发现覆盖或内容丢失时直接拒绝自动同步。已有同步目录的 MKCOL 返回 405 属正常；但随机命名的新探针或候选目录也返回 405 时，说明服务器拒绝创建文件夹（只读挂载、Go x/net/webdav 后端出错、代理拦截 MKCOL 等），单独报告为 `folder-create-refused`，不归为并发保护不足。版本基线始终是 `state.json` 内容的 SHA-256。[WebDAV RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.9.3) 仅接受 HTTPS，保留证书校验，拒绝认证跳转，使用 Basic Auth / 应用密码；兼容性由实际测试结果决定。

上传先完成媒体文件，再更新配置并回读验证。所有新客户端共享 `v1/write-lock/` 目录锁，避免不同能力模式或服务器能力变化时绕开其他设备的写入保护：默认先创建带随机归属标识的私有目录，再通过禁止覆盖的 MOVE 获取共享目录；只有返回 201 且回读归属及源移除均确认的设备能写入。MOVE 被明确拒绝时，候选目录仍保留自己的 owner.txt 才视为普通的竞争失败（稍后重试）；网关错误（502 / 503 / 504）、超时与响应丢失仍按结果不确定处理。失败方仅清理自己的候选目录，释放前再次核对归属，绝不删除别人的共享锁。经检测选用的 MKCOL 兼容方式沿用同一个共享目录。持锁后重新读取配置并比较基线，远端改变则停止写入。两种模式都比较完整文件的 SHA-256，不把哈希假装成服务器 ETag；强 ETag 模式另在 PUT 时附带 If-Match / If-None-Match。读取 `state.json` 不要求强 ETag：Cloudflare 等 CDN 压缩响应时会把强 ETag 改为弱 ETag（探针小文件不压缩，仍为强 ETag），此时不带 If-Match，仍由写入锁与 SHA-256 基线保护。部分服务（如 sabre/dav 文件后端）的 ETag 由文件大小与按秒计的修改时间生成，同一秒内两次等长写入会得到相同 ETag，只比较 ETag 会让旧基线覆盖新内容。412 会停止当前写入并重新读取。文件仍以同一版本和路径存储，合并、冲突、迁移与 Chrome 备份行为不变。下载校验格式、文件大小、图片头与尺寸、SHA-256，全部媒体准备好才替换本机数据。

独占目录锁依赖参与同步的 Lumno 客户端遵守同一协议；请升级所有设备，勿用其他程序同时修改 `state.json`。确认写入完成后释放目录；上传超时、响应丢失或后台被终止时保留锁，不按设备时间自动过期或抢占，因为尚未结束的请求可能延迟提交。若长期被占用，请先在所有设备暂停同步、确认服务端中断请求已结束，再从坚果云或 NAS 文件管理器删除同步目录下的 `v1/write-lock` 保护文件夹（含 owner.txt）并重新启用。MOVE 结果不确定时还会保留私有 lock-candidate-* 目录，可在所有设备暂停且请求结束后清理。它们是写入保护目录，请勿删除 `state.json`、`assets` 或整个同步目录。

自动同步在本机配置变化后约 1.5 秒触发，另用 Chrome alarms 每 5 分钟检查远端。同一账号的另一个浏览器（包括同一台电脑上同时开着的 Chrome 与 Firefox）正持有写入锁（`remote-locked`），或在本机读取与写入之间先提交（`remote-changed`）时，卡片显示「等待同步」而非失败，分别约 3、10、30 秒（±25% 随机抖动）后重新读取、合并并重试；三次后仍被占用才报告失败，因为这时锁可能来自结果不确定的写入。首次加入时的版本选择不自动重试。服务工作线程停止、离线或服务限流后，后续检查会重新比较完整本机状态。不同配置项可以合并；快捷方式与图标、壁纸与选图分别作为整体冲突域，避免排序和删除被错误拼接。

## 当前边界和验证

当前会下载整个自定义壁纸库；尚无按需下载、自动删除远端历史快照/孤立媒体、端到端加密、图标缓存同步。关闭开关不会删除服务器文件。配置和图片由用户自己的服务器保存，服务器管理员可读取，清理历史数据需在服务器端完成。

新增回归覆盖配置保存与开关、并行 Chrome 同步、两端合并/冲突、条件写竞争、弱/缺失 ETag 下的目录锁、目录竞争、陈旧基线拒写、上传结果不确定时保留锁、Chrome 配额、离线与暂停、后台中断恢复、损坏媒体、设置页选择、错误恢复及新页面与旧后台混用。模拟 WebDAV 服务验证了新版协议流程，包括反复开关、409 竞争、失败方内容丢失拒绝、锁归属确认失败、旧检测升级和 MOVE 不支持时的 MKCOL 退路。坚果云已有独立 MOVE 探测记录显示 409 / 201 且两方内容保留；新版的完整探测与浏览器内同步仍需实机确认，不能把旧 MKCOL 检测通过视为新版认证。2026-10-06 在本机以 HTTPS 运行 Apache mod_dav 2.4、WsgiDAV 4.3、rclone serve webdav、nginx dav、sabre/dav 4.7 文件后端与 Nextcloud 35.0.1（sqlite，非生产配置），用 `dav-lock-5` 客户端各执行 20 次连接测试及完整读写、陈旧基线拒写、10 轮双设备并发写入、媒体与快照流程：sabre/dav 有 2 次两方 MOVE 均返回 201（服务端虚报成功），被正确拒绝，其余 18 次通过；其他五种 20 次全部通过。各服务完整流程均正常，并发写入每轮至多一方提交，失败方为 `remote-locked`，无残留锁。`dav-lock-4` 在同一环境下 WsgiDAV 与 rclone 无法通过连接测试，其余仅 1–15 次通过。托管服务（Koofr、pCloud、Yandex、InfiniCLOUD 等）及群晖等 NAS 尚未实机验证，不能把本机测试视为这些服务的兼容性认证。2026-10-08 用户反馈的自建 Cloudflare Workers + R2 WebDAV（r2-webdav 一类实现）不受支持：MKCOL 对已有目录返回 405、新目录返回 201，均正常；0.9.57 首次读取 `state.json` 时 Cloudflare 压缩响应把强 ETag 改为弱 ETag，旧检查误报 `state-etag / 200`，已在 0.9.58 移除；0.9.58 的连接测试得到 `move-race / 201,201`。原因是其 MOVE 先查询目标是否存在、再逐个复制和删除对象，两次查询之间没有互斥，Overwrite: F 无法阻止并发覆盖。偶发通过只是请求恰好串行。服务端需用 R2 条件写入（如 `onlyIf: { etagDoesNotMatch: '*' }`，原子性须在线上 bucket 实测）或 Durable Object 串行化 MOVE / MKCOL 后，才能重新尝试。

相关实现：`src/shared/webdav-contract.js`、`src/background/webdav-client.js`、`src/background/webdav-sync.js`、`src/options/webdav-options.js`。
